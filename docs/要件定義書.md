## 1. 目的

オフィス入口に設置した タブレット上で、来訪者がブラウザ操作のみで受付を完了できるようにする。

受付完了時に、Chatwork の全社共通ルームへ `[toall]` 付き通知を送信し、担当者・近隣スタッフが即座に状況を把握できるようにする。事前予約のない営業来訪については対面呼出を行わず、名刺・資料投入ボックスへの案内とログ通知のみとする。

社内スタッフは管理者向け履歴画面から、過去の受付内容と通知成否を確認できる。

---

## 2. 背景・課題

- 受付専任者が常駐しないため、来訪種別ごとに適切な対応（呼出／案内のみ）を自動化したい。
- 配送は業者・要件によって「対面受領が必要」なものと「置き配でよい」ものが混在する。
- 営業の飛び込み来訪は原則お断りとし、資料投函のみ受け付ける運用にしたい。
- 通知先は全社共通の Chatwork ルーム 1 箇所に統一し、漏れなく共有する。
- Chatwork 通知の見落としや送信失敗に備え、受付履歴を画面上で確認できるようにしたい。

---

## 3. スコープ

### 3.1 対象（本システムの範囲）

- タブレットブラウザで動作する受付 UI（キオスク想定、**横置き**）
- 来訪種別ごとの入力・分岐・完了画面
- 無操作 15 秒でのトップ画面自動復帰
- Chatwork 全社共通ルームへの通知送信（置き配を含む全完了時）
- 受付ログの永続化（Supabase）
- 管理者向け受付履歴画面（パスワード認証）
- Vercel へのデプロイ

### 3.2 対象外（初期リリースでは作らないもの）

- 来訪者向けの社員検索・内線発信
- 社員マスタからの担当者自動補完
- 複数拠点・複数 Chatwork ルームへの振り分け
- ネイティブアプリ（App Store 配信）
- 名刺 OCR・カメラ撮影
- 来訪者へのメール／SMS 返信
- 履歴画面からの Chatwork 再送 UI
- 管理者の個人アカウント（メールログイン）。初期は共有パスワードとする

## 4. 用語

| 用語 | 意味 |
| --- | --- |
| 受付端末 | 入口に設置する タブレット（横置き）。Safari またはホーム画面追加の Web アプリで本システムを表示する |
| トップ画面 | 無操作時の待機画面。会社ロゴ、「ご訪問ありがとうございます。」、「受付を開始する」ボタンを表示する |

| 名刺・資料投入ボックス | タブレット横に設置する物理ボックス。営業来訪時の投函先 |

## 5. 利用環境・前提

### 5.1 物理環境

- 設置端末：タブレット**横置き（ランドスケープ）固定**
- 操作：タッチのみ（マウス・外部キーボードなし）
- タブレット横に「名刺・資料投入ボックス」を設置する
- Guided Access（アクセスガイド）等でブラウザ以外への離脱を抑制することを推奨する
- 画面回転は横向きにロックする（CSS / viewport で横置きレイアウトを前提とし、端末側でも横向きロックを推奨）

### 5.2 ソフトウェア環境

| 項目 | 内容 |
| --- | --- |
| クライアント（受付） | タブレット上のブラウザ（Safari 想定）。PWA（ホーム画面追加）対応を推奨 |
| クライアント（履歴） | 社内 PC・スマートフォン・タブレットのブラウザ |
| 使用言語 | TypeScript |
| フロント／API | Next.js（App Router）を想定 |
| デプロイ | Vercel |
| データベース | Supabase（PostgreSQL） |
| 外部連携 | Chatwork API |

### 5.3 利用者

| アクター | 説明 | 認証 |
| --- | --- | --- |
| 来訪者 | 受付操作を行う社外の人 | なし（公開キオスク） |
| 社内スタッフ | Chatwork 通知を受けて対応する。履歴画面も閲覧する | Chatwork 側／履歴は共有パスワード |
| システム管理者 | 環境変数・デプロイ・管理者パスワードを管理する | Vercel / Supabase 管理画面 |

## 6. システム概要

```
[来訪者] → [タブレット横置き / ブラウザ]     [社内スタッフ]
                │                            │
                ▼                            ▼
        [受付 Web アプリ (Vercel)] ←── [履歴画面 /admin]
                │
                ├── 受付ログ保存 → [Supabase]
                └── 通知送信     → [Chatwork 全社共通ルーム]
                                      └ [toall] + 種別ごとの info テンプレート
```

- Chatwork API トークンはクライアントに出さない。通知送信はサーバー側 API 経由とする。
- 受付記録は監査・トラブル確認のため Supabase に保存する。
- 履歴画面は受付キオスクからはリンクせず、URL とパスワードを知っているスタッフのみが使う。

```

 ├─ お約束のある方
 │    └─ 入力画面 → 完了画面（15秒でトップへ）
 ├─ 採用・面接の方
 │    └─ 入力画面 → 完了画面（15秒でトップへ）
 ├─ 配送・納品業者様
 │    ├─ 業者選択
 │    │    ├─ Amazon / ヤマト運輸 / 佐川急便 / 日本郵便
 │    │    │    └─ 要件選択
 │    │    │         ├─ 受領印が必要（呼び出し）→ 呼び出し中画面（15秒でトップへ）
 │    │    │         └─ 置き配・受領印不要     → 完了画面（15秒でトップへ）※Chatwork通知あり
 │    │    ├─ その他
 │    │    │    └─ 社名入力（必須）→ 要件選択（同上）
 │    │    └─ Nash / 水の納品
 │    │         └─ 要件選択をスキップ → 呼び出し中画面（15秒でトップへ）
 └─ 新規のご提案・営業の方
      └─ 案内画面 → 「確認してトップへ戻る」または 15秒無操作でトップへ
         （離脱時に Chatwork へログ通知）
```

### 7.2 管理者（履歴）

```
/admin/login（パスワード）
 └─ /admin（受付履歴一覧）
      └─ フィルタ変更・ページング（同一画面）
```

履歴画面は来訪者フローから独立する。無操作 15 秒リセットの対象外とする。

### 7.3 無操作リセット（キオスクのみ）

- 用件選択画面の放置も含め、**最後の操作から 15 秒**でトップ画面へ自動復帰する。
- タイマーはタップのたびにリセットする。
- トップ画面（歓迎画面）表示中はタイマーを動かさない。

## 8. 機能要件

### FR-01 トップ画面（待機画面）

- 会社ロゴ（`logo.png`／株式会社 Y Agency）を画面上部に表示する。
- メッセージ **「ご訪問ありがとうございます。」** を中央に大きく表示する。
- ボタン **「受付を開始する」** を 1 つ置く。タップで用件選択画面へ進む。
- 受付画面上に履歴・管理へのリンクは置かない。

### FR-01b 用件選択画面

- タイトル **「受付」** を表示する。
- サブタイトル **「ご用件をお選びください」** を表示する。
- 横置き前提で、以下 4 つのボタンを **2×2** に大きく配置する。

| ボタン | 遷移先 |
| --- | --- |
| お約束のある方 | 約束来訪の入力画面 |
| 採用・面接の方 | 面接の入力画面 |
| 配送・納品業者様 | 業者選択画面 |
| 新規のご提案・営業の方 | 営業案内画面 |

### FR-02 お約束のある方

- 画面注記を表示する。
  - 「※事前の約束がない営業・ご提案の方はトップに戻り『新規のご提案・営業の方』をお選びください」
- 入力項目

| 項目 | 必須 | 備考 |
| --- | --- | --- |
| 貴社名 | 必須 | テキスト |
| お名前 | 必須 | テキスト |
| 訪問予定の担当者名 | 任意 | 未入力時は通知上「未指定」 |

- 送信後、完了画面に「担当者に通知しました。少々お待ちください。」を表示する。
- Chatwork へ【お約束のある方】テンプレートで通知する。担当者未指定時は注記「※担当者が未指定の場合は、お近くのスタッフがご対応をお願いします。」を含める。

### FR-03 採用・面接の方

| 項目 | 必須 | 備考 |
| --- | --- | --- |
| お名前（フルネーム） | 必須 | テキスト |

- 送信後、完了画面に「採用担当に通知しました。少々お待ちください。」を表示する。
- Chatwork へ【採用・面接】テンプレートで通知する。

### FR-04 配送・納品業者様

#### 8.4.1 業者選択

次の 7 ボタンを表示する。横置きでは見切れないよう折り返し配置する。

| 業者 | 次の動作 |
| --- | --- |
| Amazon | 要件選択へ |
| ヤマト運輸 | 要件選択へ |
| 佐川急便 | 要件選択へ |
| 日本郵便 | 要件選択へ |
| Nash | 要件選択をスキップし、呼び出し中画面へ。通知は Nash 専用テンプレート |
| 水の納品 | 要件選択をスキップし、呼び出し中画面へ。通知は水の納品専用テンプレート |
| その他 | 社名入力へ。入力後に要件選択へ |

#### 8.4.2 要件選択（Amazon / ヤマト運輸 / 佐川急便 / 日本郵便 / その他）

| 選択 | 動作 |
| --- | --- |
| 受領印が必要（呼び出し） | 呼び出し中画面へ。Chatwork は一般宅配便（呼び出し）テンプレート |
| 置き配・受領印不要 | 完了画面へ。Chatwork は置き配テンプレート（9.4）**必ず送信する** |

#### 8.4.3 完了メッセージ

- 対面呼出が発生するケース（受領印必要、Nash、水の納品）  
  「担当者を呼び出しました。少々お待ちください。」
- 置き配・受領印不要（対面呼出なし、Chatwork 通知あり）  
  「ご案内ありがとうございました。荷物は所定の場所へお置きください。」

### FR-05 新規のご提案・営業の方

- 対面呼出は行わない。Chatwork へのログ通知のみ行う。
- 案内文を全画面表示する。

> ご来訪誠にありがとうございます。  
> 現在、事前の予約がないご提案・営業等のご面会はお断りしております。  
> 誠にお手数ですが、ご持参いただきましたお名刺や資料等は、**タブレット横の『名刺・資料投入ボックス』**へお入れください。  
> 担当部署にて確認の上、必要な場合のみご連絡いたします。

- ボタン：「確認してトップへ戻る」
- 通知送信タイミング：案内画面を離れるとき（ボタンタップ、または 15 秒タイムアウト）に **1 回だけ**送信する。同一表示中の二重送信は禁止する。

### FR-06 Chatwork 通知

- 通知先は全社共通ルーム 1 箇所。
- すべての通知本文の先頭に `[toall]` を付与する。
- メッセージは Chatwork の info 記法を用いる。
- **置き配・受領印不要も含め、受付完了時は必ず通知する。**
- 送信失敗時は来訪者に技術的なエラー詳細を出さない。完了画面は出しつつ、サーバー側で失敗ログを残す（必要ならリトライ 1 回）。
- 詳細フォーマットは「9. Chatwork 通知仕様」を正とする。

### FR-07 受付ログ保存

受付のたびに Supabase へ 1 件保存する。保存項目は「10. データ要件」を参照。履歴画面はこのテーブルを表示する。

### FR-08 共通 UI 動作（キオスク）

- 各入力・選択画面に「戻る」（1 画面戻る）を置く。
- 必須未入力では送信できない。送信ボタンは無効化するか、送信時にインラインでエラーを出す。
- 日本語入力（かな漢字）を前提とする。入力欄は適切な `inputmode` / `autoComplete` を設定する。
- ボタンは タブレット横置きで押しやすいサイズ（推奨タップ領域 44pt 以上、受付ボタンはさらに大きく）とする。
- 横スクロールを発生させず、タブレット横画面内に収める。

### FR-09 管理者向け受付履歴画面

初期リリースに含める。

#### 8.9.1 アクセス

- URL：`/admin`（ログインは `/admin/login`）
- 受付キオスク（トップ画面）からはリンクしない。
- 認証：環境変数で持つ **共有パスワード**（個人アカウントは作らない）。
- 認証成功後は HttpOnly Cookie でセッションを維持する。
- 未認証で `/admin` にアクセスした場合はログイン画面へリダイレクトする。
- ログアウトボタンを履歴画面に置く。

#### 8.9.2 一覧表示

- 受付日時の新しい順で一覧表示する。
- 日時は **日本時間（JST）** で表示する。
- 1 ページあたり 50 件。ページングする。

| 列 | 内容 |
| --- | --- |
| 日時 | `YYYY/MM/DD HH:mm` |
| 種別 | お約束 / 面接 / 配送 / 営業 |
| 会社名 | 約束来訪のみ。他は「—」 |
| お名前 | 該当しない種別は「—」 |
| 担当者 | 未入力は「未指定」。該当しない種別は「—」 |
| 業者・要件 | 配送のみ（例：Amazon / 置き配） |
| 通知 | 成功 / 失敗 |

#### 8.9.3 フィルタ

| フィルタ | 内容 |
| --- | --- |
| 期間 | 開始日・終了日。初期値は当日 |
| 種別 | すべて / お約束 / 面接 / 配送 / 営業 |
| 通知状態 | すべて / 成功 / 失敗 |

#### 8.9.4 失敗時の見え方

- 通知失敗の行は視覚的に目立たせる（色分け）。
- 失敗理由（`error_message`）は一覧上または行の展開で確認できるようにする。
- 初期リリースでは画面からの再送は行わない。

#### 8.9.5 画面の前提

- PC ブラウザを主対象とする（スマートフォンでも閲覧できるレスポンシブとする）。
- 受付キオスクの 15 秒リセットは適用しない。

## 9. Chatwork 通知仕様

共通ルール：

- 先頭に `[toall]` を付ける。
- プレースホルダは実際の入力値に置換する。
- 担当者名が空のときは「未指定」と表示する。

### 9.1 お約束のある方

```
[toall]
[info][title]🏢 【来客】{お名前}様（担当：{担当者名}）[/title]
お客様がお見えです。

企業名：{貴社名}
お名前：{お名前} 様
担当者：{担当者名}
[hr]※担当者が未指定の場合は、お近くのスタッフがご対応をお願いします。[/info]
```

- `{担当者名}` は未入力時「未指定」。
- title 内の担当者も同様。

### 9.2 採用・面接

```
[toall]
[info][title]👔 【面接】採用担当者様[/title]
面接の方が到着されました。ご対応をお願いします。

お名前：{お名前} 様[/info]
```

### 9.3 配送：一般宅配便（呼び出し選択時）

対象：Amazon / ヤマト運輸 / 佐川急便 / 日本郵便 / その他 かつ「受領印が必要（呼び出し）」

```
[toall]
[info][title]📦 【配送】受領印のお願い[/title]
配送業者様がいらっしゃいました。エントランスでのご対応をお願いします。

業者名：{業者名}
要件：受領印が必要[/info]
```

### 9.4 配送：置き配・受領印不要（確定）

対象：Amazon / ヤマト運輸 / 佐川急便 / 日本郵便 / その他 かつ「置き配・受領印不要」  
**Chatwork 通知する（確定）。**

```
[toall]
[info][title]📦 【配送】置き配のご案内済み[/title]
配送業者様が置き配（受領印不要）を選択されました。
対面対応は不要です。荷物の到着をご確認ください。

業者名：{業者名}
要件：置き配・受領印不要[/info]
```

### 9.5 配送：Nash（対面受け取り必須）

```
[toall]
[info][title]🍱 【要対応】Nashが到着しました[/title]
Nashの配達業者様が到着されました。受領・対面対応をお願いします。
[hr]※冷凍品のため、受取後はすみやかに冷凍庫へ格納してください。[/info]
```

### 9.6 配送：水の納品（対面受け取り必須）

```
[toall]
[info][title]💧 【要対応】お水の納品が到着しました[/title]
ウォーターサーバー用のお水が届きました。受領・対面対応をお願いします。
[hr]※手運びでの受け取り対応をお願いします。（空ボトルの回収はありません）[/info]
```

### 9.7 新規のご提案・営業（資料投入通知）

```
[toall]
[info][title]📄 【営業来訪】資料投入のご案内済み[/title]
新規のご提案・営業の方が来訪されました。
受付画面にて名刺・資料投入ボックスへの投函をご案内しています。
[hr]※対面対応は不要です。後ほど受付ボックスをご確認ください。[/info]
```

## 10. データ要件

### 10.1 テーブル `reception_logs`

| カラム | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| id | uuid | はい | 主キー |
| created_at | timestamptz | はい | 受付日時（JST 表示はアプリ側） |
| visit_type | text | はい | `appointment` / `interview` / `delivery` / `sales` |
| company_name | text | いいえ | 約束来訪の貴社名 |
| visitor_name | text | いいえ | 来訪者名 |
| staff_name | text | いいえ | 担当者名 |
| carrier | text | いいえ | 配送業者名 |
| delivery_need | text | いいえ | `stamp_required` / `drop_off` / `must_receive` |
| chatwork_status | text | はい | `sent` / `failed` |
| chatwork_message_id | text | いいえ | 送信成功時のメッセージ ID |
| error_message | text | いいえ | 送信失敗時の概要 |

- Row Level Security：匿名クライアントからの直接 insert / select は禁止。サーバー（サービスロール）経由のみ読み書きする。
- 履歴画面の参照もサーバー API 経由とする。
- 個人情報（氏名・会社名）を含むため、保持期間は運用で定める（初期案：1 年）。

### 10.2 環境変数

| --- | --- |

## 12. 画面要件（概要）

| 画面 | 向き・対象 | 主要要素 |
| --- | --- | --- |
| トップ | タブレット横置き | ロゴ、タイトル「受付」、サブタイトル、4 ボタン（2×2） |
| 約束入力 | タブレット横置き | 注記、貴社名、お名前、担当者名、送信、戻る |
| 面接入力 | タブレット横置き | お名前、送信、戻る |
| 業者選択 | タブレット横置き | 7 業者ボタン、戻る |
| 要件選択 | タブレット横置き | 受領印が必要 / 置き配・受領印不要、戻る |
| 完了／呼び出し中 | タブレット横置き | メッセージのみ（操作不要）。15 秒でトップへ |
| 営業案内 | タブレット横置き | 全文案内、「確認してトップへ戻る」 |

ビジュアル方針：

- 背景は明るく、コントラストを高くする。
- ブランドカラーはロゴのグリーン系を基調とする。
- 完了画面は大きく読みやすい文言のみとする。
- 横置きでは左右の余白を活かし、ボタンを大きく取る。

## 14. 制約・前提

- Chatwork ルームは 1 箇所。担当者個人への To やルーム振り分けは初期対象外。
- `[toall]` はルーム全員に通知が飛ぶ。運用上のノイズは承知のうえで採用する。
- 「その他」配送では社名の入力を必須とし、Chatwork の業者名には入力した社名を用いる。
- ロゴファイルはリポジトリ内の `logo.png` を使用する。
- 営業案内の「画面を閉じたタイミング」は、キオスクではタブを閉じないため、**ボタンタップまたは 15 秒タイムアウト**を「画面を離れたタイミング」とみなす。
- 受付 タブレットは横置き固定。縦向き表示は初期対象外（回転しても横レイアウトを維持、または案内を出してもよい）。
- 履歴画面の認証は共有パスワードのため、パスワードの共有範囲は社内の必要最小限とする。

## 17. 受け入れ条件

以下を満たせば初期リリース完了とする。

1. タブレットの Safari **横置き**でトップ〜各フローが操作でき、画面内に収まる。
2. トップにロゴ、タイトル「受付」、サブタイトル、4 ボタン（2×2）が表示される。
3. 4 種別すべての正常系で、指定フォーマットの Chatwork 通知が全社共通ルームに届く。
4. **置き配完了時にも** Chatwork 通知が届く。
5. すべての通知に `[toall]` が付く。
6. Nash / 水の納品は要件選択を出さず、専用通知になる。
7. 営業フローは対面呼出メッセージを出さず、案内文とログ通知のみである。
8. 入力途中および完了画面放置から 15 秒でトップに戻る。
9. 必須項目未入力では送信できない。
10. Vercel にデプロイでき、環境変数で Chatwork / Supabase / 管理者パスワードを切り替えられる。
11. 受付記録が Supabase に残る。
12. `/admin` はパスワードなしでは閲覧できない。
13. 履歴画面で日時・種別・入力内容・通知成否を一覧でき、期間・種別・通知状態で絞り込める。
14. 受付トップから履歴画面へ到達するリンクが無い。

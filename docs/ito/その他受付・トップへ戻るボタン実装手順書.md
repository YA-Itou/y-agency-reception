# 「その他」受付・完了画面「トップへ戻る」ボタン 実装手順書

## 1. 目的

受付の用件選択画面に「その他」を追加し、来訪者が「会社名」と「名前」を入力して受付できるようにする。

あわせて、受付完了後の共通完了画面に「トップへ戻る」ボタンを追加し、15秒の自動復帰を待たずに待機中のトップ画面へ戻れるようにする。

## 2. 合意済みの仕様

- 用件選択画面に5つ目のメニューとして「その他」を表示する。
- 「その他」を押すと専用入力画面へ遷移する。
- 専用入力画面では次の2項目を必須入力とする。
  - 会社名
  - 名前
- 両項目が空白文字だけの場合も未入力として扱い、「受付する」ボタンを有効にしない。
- 送信中は二重送信を防止する。
- 受付完了後は既存の共通完了画面を表示し、Chatwork通知と受付履歴保存の対象にする。
- 共通完了画面に「トップへ戻る」ボタンを表示する。
- ボタンを押すと入力内容などの一時状態を初期化し、待機中のトップ画面（「受付を開始する」がある画面）へ即時に戻る。
- 既存の無操作15秒によるトップ画面への自動復帰は維持する。
- 営業案内画面にはすでに「確認してトップへ戻る」があるため、同じ役割のボタンを重複追加しない。

## 3. 画面遷移

```text
待機中のトップ画面
  └─ 受付を開始する
      └─ 用件選択画面
          └─ その他
              └─ その他受付入力画面
                  ├─ 戻る → 用件選択画面
                  └─ 受付する
                      └─ 共通完了画面
                          ├─ トップへ戻る → 待機中のトップ画面
                          └─ 15秒無操作 → 待機中のトップ画面
```

## 4. 実装方針

### 4.1 用件選択画面へ「その他」を追加する

対象: `src/components/kiosk/HomeScreen.tsx`

1. `HomeCard["id"]` に `other` を追加する。
2. `cards` に次の内容のカードを追加する。
   - 日本語表示: `その他`
   - 英語表示: `Other`
   - 補足文: `会社名とお名前をご入力ください`
   - 既存カードと判別でき、画面全体の配色にもなじむアクセント色とアイコン
3. 5枚になっても横置きタブレットの1画面内に収まり、各ボタンのタップ領域が狭くならないようレイアウトを調整する。
   - 6列グリッドを用い、5枚すべてを各2列幅に統一する。上段に3枚、下段に2枚を中央寄せで配置する。
   - 1024×768と1920×1080相当で、縦スクロールやカード内テキストの欠けがないことを確認する。

### 4.2 「その他」専用入力画面を作る

対象: `src/components/kiosk/FormScreens.tsx`

1. `OtherReceptionScreen` を追加する。
2. 既存の `ScreenCard`、`Field`、`BackButton`、`PrimaryButton` を再利用し、既存画面と見た目・操作感をそろえる。
3. `companyName` と `visitorName`、`submitting`、`onChange`、`onBack`、`onSubmit` をpropsとして受け取る。
4. 入力欄は次の仕様にする。
   - `会社名`: 必須、`autoComplete="organization"`
   - `お名前`: 必須、`autoComplete="name"`
5. `companyName.trim()` と `visitorName.trim()` がどちらも空でない場合のみ送信可能にする。
6. フォーム送信時はブラウザ既定の再読み込みを止め、送信中でなければ `onSubmit` を呼ぶ。
7. 送信中は「戻る」と「受付する」を無効化し、送信ボタンの文言を `送信中…` にする。

### 4.3 キオスクの状態遷移と送信処理を追加する

対象: `src/components/kiosk/KioskApp.tsx`

1. `OtherReceptionScreen` を読み込む。
2. 用件選択で `other` が選ばれたとき、フォーム状態を初期化して `other` ステップへ遷移する。
3. `step === "other"` の描画分岐を追加する。
4. 戻る操作には既存の `goMenu` を使い、入力値を消して用件選択画面へ戻す。
5. 送信時は既存の `finish` を利用し、次のpayloadを `/api/reception` に送る。

```ts
{
  visitType: "other",
  companyName: form.companyName,
  visitorName: form.visitorName,
}
```

6. 完了種別に `other` を指定し、その他受付用の完了メッセージを表示する。
7. 共通完了画面へ `resetHome` を渡し、「トップへ戻る」操作で次の状態を初期化する。
   - `step`
   - `form`
   - `carrier`
   - `submitting`
   - `salesSent`

### 4.4 型と表示定数を拡張する

対象:

- `src/lib/types.ts`
- `src/lib/constants.ts`

変更内容:

1. `VisitType` に `other` を追加する。
2. `KioskStep` に `other` を追加する。
3. `CompleteKind` に `other` を追加する。
4. `VISIT_TYPE_LABEL` に `other: "その他"` を追加する。
5. `COMPLETE_MESSAGE` にその他受付用メッセージを追加する。
   - 表示案: `受付内容を通知しました。\n少々お待ちください。`

型を先に更新してから各分岐を実装し、TypeScriptの網羅性チェックで対応漏れを見つけやすくする。

### 4.5 APIで「その他」を受け付け、入力を検証する

対象: `src/app/api/reception/route.ts`

1. `isPayload` の受付可能な種別に `other` を追加する。
2. `validate` にその他受付の検証を追加する。
   - `companyName` が未入力または空白文字だけなら400を返す。
   - `visitorName` が未入力または空白文字だけなら400を返す。
   - エラー文言は `会社名とお名前は必須です` とする。
3. クライアント側のボタン制御だけに依存せず、直接APIを呼ばれた場合も不正データを保存・通知しないようにする。

### 4.6 Chatwork通知文を追加する

対象: `src/lib/chatwork.ts`

1. `buildChatworkBody` の `switch` に `case "other"` を追加する。
2. その他受付用の本文生成関数を追加する。
3. `companyName` と `visitorName` は既存通知と同じく `trim()` 後の値を使う。
4. 通知文は次を基本とする。

```text
[toall]
[info][title]🔔 【その他】来訪者のお知らせ[/title]
その他のご用件でお客様がお見えです。ご対応をお願いします。

会社名：{会社名}
お名前：{名前} 様[/info]
```

これにより、既存と同じ全社共通ルームに通知しつつ、受付種別と来訪者情報を判別できるようにする。

### 4.7 受付ログのDB制約を更新する

新規ファイル: `supabase/migrations/002_add_other_visit_type.sql`

既存の `reception_logs.visit_type` には4種別だけを許可するCHECK制約があるため、アプリの変更より先に本番DBへマイグレーションを適用する。

実施内容:

1. 既存の `reception_logs_visit_type_check` を削除する。
2. `other` を含むCHECK制約を同じ列へ再作成する。

許可値:

```text
appointment / interview / delivery / sales / other
```

既存データや列は削除せず、許可値だけを拡張する。マイグレーション適用前にアプリを公開すると `other` の履歴保存だけが失敗するため、適用順序に注意する。

### 4.8 管理画面で「その他」を扱えるようにする

対象: `src/components/admin/HistoryApp.tsx`

1. 種別フィルターに `その他`（値は `other`）を追加する。
2. 一覧の種別欄では `VISIT_TYPE_LABEL` を通じて `その他` と表示する。
3. 会社名・お名前は既存列をそのまま利用する。
4. 担当者列と業者・要件列はその他受付では `—` のままとする。

### 4.9 共通完了画面に「トップへ戻る」を追加する

対象:

- `src/components/kiosk/FlowScreens.tsx`
- `src/components/kiosk/KioskApp.tsx`

変更内容:

1. `CompleteScreen` に `onHome: () => void` を追加する。
2. 完了メッセージの下に、既存の `PrimaryButton` を使って `トップへ戻る` ボタンを表示する。
3. 自動復帰の案内文 `まもなくトップ画面に戻ります` は残し、ボタンの下または上に読みやすい間隔で配置する。
4. `KioskApp` から `onHome={resetHome}` を渡す。
5. 対象は共通完了画面を利用する次の受付とする。
   - お約束
   - 採用・面接
   - 配送（呼び出し、置き配）
   - その他
6. 営業は既存の `確認してトップへ戻る` で同じ操作が可能なため、現状の導線を維持する。

### 4.10 ドキュメントを更新する

対象:

- `docs/要件定義書.md`
- `README.md`

更新内容:

1. 用件選択を「4ボタン」から「5ボタン」へ変更する。
2. 画面遷移に「その他 → 会社名・名前入力 → 完了」を追記する。
3. `visit_type` の許可値に `other` を追記する。
4. 完了画面から手動でトップへ戻れることを追記する。
5. READMEの機能一覧へ「その他受付」を追記する。
6. Supabaseの追加マイグレーション適用手順を追記する。

## 5. 推奨実装順序

1. `types.ts` と `constants.ts` を拡張する。
2. DBマイグレーションを作成する。

8. `CompleteScreen` に「トップへ戻る」ボタンを追加する。
9. 管理画面の種別フィルター・表示を更新する。

11. 静的検査、ビルド、手動確認を行う。

## 6. 検証手順

### 6.1 静的検査・ビルド

リポジトリ直下で次を実行する。

```bash
npm run lint
npm run build
```

確認事項:

- ESLintエラーがない。
- TypeScriptの型エラーがない。
- Next.jsの本番ビルドが成功する。
- `VisitType` 追加に伴う分岐漏れがない。

### 6.2 用件選択画面

1. 横向き1024×768相当で5枚すべてが画面内に表示される。
2. 横向き1920×1080相当でもカード間の余白と配置が不自然でない。
3. 「その他」を押すと専用入力画面へ進む。
4. 既存4メニューの遷移が変わっていない。

### 6.3 その他受付入力

以下を確認する。

| 会社名 | 名前 | 期待結果 |
| --- | --- | --- |
| 空 | 空 | 受付不可 |
| 入力あり | 空 | 受付不可 |
| 空 | 入力あり | 受付不可 |
| 空白のみ | 入力あり | 受付不可 |
| 入力あり | 空白のみ | 受付不可 |
| 入力あり | 入力あり | 受付可能 |

追加確認:

- 「戻る」で用件選択画面へ戻り、再度開いたときに古い入力が残らない。
- 「受付する」を連打しても通知・ログが重複しない。
- 送信後にその他受付用の完了メッセージが表示される。

### 6.4 API

1. `visitType: "other"` かつ会社名・名前ありで200になる。
2. 会社名欠落、名前欠落、空白文字だけの値は400になる。
3. 未知の `visitType` は従来どおり400になる。
4. 正常時のChatwork通知に会社名・名前・その他受付であることが含まれる。

### 6.5 受付履歴・DB

1. マイグレーション後、`visit_type = 'other'` のログを保存できる。
2. 既存4種別のログも引き続き保存できる。
3. 管理画面に種別 `その他`、入力した会社名・名前が表示される。
4. 種別フィルターで `その他` のみを絞り込める。

### 6.6 トップへ戻る動作

1. お約束、面接、配送、その他の各完了画面に `トップへ戻る` が表示される。
2. ボタンを押すと即座に待機中のトップ画面へ戻る。
3. 次の受付開始時に前回の会社名・名前・担当者名・配送業者が残っていない。
4. ボタンを押さない場合も、既存どおり15秒無操作でトップ画面へ戻る。
5. 営業案内画面の `確認してトップへ戻る` と15秒無操作時の通知が従来どおり動く。

## 7. 受け入れ条件

- 用件選択画面から「その他」を選択できる。
- その他受付は会社名と名前の両方を入力しない限り送信できない。
- 正常送信時にChatwork通知とSupabaseの受付ログ保存が行われる。
- 管理画面でその他受付を表示・絞り込みできる。
- 共通完了画面の「トップへ戻る」で、15秒を待たずに待機中のトップ画面へ戻れる。
- 手動復帰後に前回の入力状態が残らない。
- 既存の4受付フローと自動復帰に回帰不具合がない。
- `npm run lint` と `npm run build` が成功する。

## 8. 注意事項

- DBのCHECK制約更新を先に適用し、その後にアプリをデプロイする。
- 現在の通知処理はChatwork送信が失敗しても完了画面へ進む既存仕様である。本対応では挙動を変更しない。
- 無操作タイマーはポインター・タッチ・キー操作で延長される既存仕様を維持する。「トップへ戻る」ボタン押下時はタイマー満了を待たず `resetHome` を直接実行する。
- 本手順書では「会社名」「名前」をどちらも必須として扱う。
